The machine-readable contract is the OpenAPI 3.1 document generated by FastAPI at `/api/v1/openapi.json`. CI publishes it as a build artifact. This document defines the **standards** and the **endpoint catalogue**. Where the two differ, the generated spec is the source of truth for request/response shapes, and this document is the source of truth for behaviour.

## 1. Standards

### 1.1 Basics
- **Base path:** `/api/v1`. It is served from the same origin as the web app (A-01 §4).
- **Format:** JSON only, UTF-8, `snake_case` fields. Timestamps are ISO-8601 in UTC (`2026-10-23T10:15:00Z`); dates are `YYYY-MM-DD`.
- **IDs:** UUID strings.
- **Methods:** `GET` reads; `POST` creates or runs commands; `PUT` replaces idempotently; `PATCH` makes partial updates (JSON Merge Patch); `DELETE` removes.
- **Versioning:** the major version is in the path. Additive changes (new optional fields, new endpoints) are non-breaking. Breaking changes need `/api/v2` or a 90-day deprecation, announced with `Deprecation` and `Sunset` headers.

### 1.2 Authentication
- Cookies `access_token` (15 min) and `refresh_token` (path `/api/v1/auth/refresh`). Both are httpOnly, Secure and SameSite=Lax.
- Requests that change state must send the `X-CSRF-Token` header, matching the `csrf_token` cookie (double submit).
- **401** means not authenticated or the token expired. The client then calls `POST /auth/refresh` once and retries.

### 1.3 Errors (RFC 9457 problem+json)

```json
{
  "type": "https://docs.<domain>/errors/lm_locked",
  "title": "Learning module is locked",
  "status": 403,
  "code": "lm_locked",
  "detail": "Score at least 80% in the LM2 chapter quiz to open LM3.",
  "request_id": "01JB...",
  "errors": [],
  "meta": {"unmet": [{"condition": "quiz_best_pct", "lm_id": "...", "required": 80, "actual": 70}]}
}
```

| Status | When | Example `code` |
|---|---|---|
| 400 | Malformed request | `bad_request` |
| 401 | Not authenticated | `unauthenticated`, `token_expired` |
| 403 | Authenticated but not allowed | `forbidden`, `lm_locked`, `not_entitled`, `consent_required` |
| 404 | Not found **or not visible** to the caller (no existence leaks) | `not_found` |
| 409 | Version conflict, duplicate | `version_conflict`, `duplicate` |
| 422 | Validation failed (field errors in `errors[]`) | `validation_failed` |
| 429 | Rate limited (`Retry-After` header set) | `rate_limited` |
| 500/503 | Server error / maintenance | `internal_error`, `unavailable` |

### 1.4 Pagination, filtering, sorting
- Cursor pagination: `?limit=50&cursor=<opaque>`. The response has `{ "items": [...], "next_cursor": "..." | null }`. The maximum limit is 200.
- Filters are explicit query parameters (`?status=published&subject_id=...`). Sorting: `?sort=-created_at` (allow-listed fields only).

### 1.5 Concurrency and idempotency
- Editable admin resources return an `ETag` (the entity version). `PATCH` and `PUT` require `If-Match`; a mismatch gives `409 version_conflict`.
- `POST` endpoints that create resources accept an `Idempotency-Key` (UUID). The same key with the same body returns the original response for 24 h; the same key with a different body gives 409.

### 1.6 Rate limits (per IP plus per user; Redis token bucket)

| Endpoint group | Limit |
|---|---|
| `POST /auth/otp/request` | 5 / hour / destination; 20 / hour / IP |
| `POST /auth/otp/verify`, `/auth/staff/login` | 10 / 15 min / IP; account lock per BR |
| Progress heartbeats | 12 / minute / user / resource |
| Search | 60 / minute / user |
| Everything else | 300 / minute / user |

### 1.7 Security headers (API)
`Cache-Control: no-store` on authenticated responses, `X-Content-Type-Options: nosniff`, and `Strict-Transport-Security` set at the edge. CORS is not enabled (single origin).

## 2. Endpoint catalogue — Phase 1

Legend: **Auth** column = required permission (P-06) or `public`. Requests from students are also checked for entitlement and unlock as noted.

### 2.1 Auth

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/auth/otp/request` | public | Body `{channel: "sms"\|"email", destination, purpose: "login"\|"signup"}` → `202 {challenge_id, expires_in}` |
| POST | `/auth/otp/verify` | public | `{challenge_id, code}` → existing user: sets cookies, `200 {user}`; new user: `200 {signup_token}` |
| POST | `/auth/signup` | signup_token | `{full_name, dob, email?, consents:[{purpose, granted}], notice_version}` → `201 {user, status}` |
| POST | `/auth/staff/login` | public | `{email, password}` → `200 {mfa_required: true, mfa_token}` |
| POST | `/auth/staff/mfa` | mfa_token | `{totp_code}` → sets cookies |
| POST | `/auth/staff/mfa/enrol` | staff (first login) | Returns a TOTP provisioning URI; confirm with a code; returns recovery codes once |
| POST | `/auth/refresh` | refresh cookie | Rotates tokens; reuse detected → family revoked, 401 |
| POST | `/auth/logout` | any | Revokes the current session |
| GET | `/me` | any | Profile, roles, status, feature flags |
| PATCH | `/me` | any | Name, email (email change triggers re-verification) |
| GET | `/me/sessions` · DELETE `/me/sessions/{id}` | any | Device list and sign-out |

```json
  "id": "0192f0b6-...",

  "lms": [

    {"id": "...", "lm_no": 2, "title": "Equity Market Organization", "state": "unlocked", "completion_pct": 40, "eoc_completed": false},
    {"id": "...", "lm_no": 3, "title": "Market Efficiency", "state": "locked",

```

**`POST /api/v1/resources/{id}/progress`**
```json
// request

{"completed": false, "coverage_pct": 62, "last_position_s": 315}
```
